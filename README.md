# force-jv880

A port of [`schwung-jv880`](https://github.com/charlesvestal/schwung-jv880)'s
**Mini-JV** — a Roland JV-880 PCM rompler emulation, itself built on
[Nuked-SC55](https://github.com/nukeykt/Nuked-SC55) by nukeykt and
[mini-jv880](https://github.com/giulioz/mini-jv880) (juce-jv880) by giulioz —
from Ableton Move to the **Akai Force** running
[MockbaMod](https://github.com/MockbaTheBorg/MockbaMod).

Like [`force-maze`](https://github.com/sd88me/force-maze), this is a real
**audio DSP synth**, not a MIDI generator: it renders actual JV-880 samples
and mixes them into what the Force's own app reads from its audio-in capture
device, so the voice comes out on a normal Audio-In track, fed by a virtual
MIDI port.

## Features

- Full Roland JV-880 PCM rompler emulation — real MCU/DSP core, real ROM
  waveforms, real patch/performance data — not a re-implementation from
  scratch.
- Multi-tone patches (up to 4 tones), full per-tone editing: wave/FXM/pitch,
  pitch/filter/amp envelopes, LFO 1 and 2.
- SR-JV80 expansion card support (see ROMs and expansion cards below).
- Bank/expansion browsing with real patch names.
- 8 macro knobs plus reverb/chorus sends, exposed to both the web panel and
  Q-Link.
- Multi-destination output: stereo into Audio-In 1/2, stereo into Out 3/4, or
  either channel alone.
- On-device touchscreen editor (see below) and a full web panel with every
  chain parameter exposed.

## Using force-jv880

Control the engine from a Force MIDI track via the virtual `JV-880:In (Mockba)`
port (notes + CC, mapped through Q-Link — see the `.xtk` template below), or
from its web panel at `http://<force-ip>:8306`.

### Touchscreen GUI (shadow mode)

A full editor page for the Force's own touchscreen, rendered by
[`force-shadow`](https://github.com/sd88me/force-shadow): open it with
`SHIFT+SCENE-3`, start/stop the engine from the ENGINE cell in the top bar.
Charcoal panels with a yellow-green dot-matrix LCD top bar (nameplate, bank,
patch stepper, engine state).

| Tab | Contents |
|-----|----------|
| PLAY | Output (destination/level, octave, patch level/pan), the 8 macros, reverb/chorus sends, tone on/off |
| PATCH | Control (analog feel, key assign, solo legato, velocity switch), bend/portamento, reverb, chorus |
| TONE 1-4 | Wave/FXM/pitch, **draggable Pitch/Filter/Amp envelope graphs** (drag a point: x = time, y = level), LFO 1 and 2 |
| BANKS | Bank/expansion list (tap = jump to that bank) and a paged patch list |

Mockups are in [`docs/mockups/`](docs/mockups); layout notes in
[`docs/SHADOW-GUI-PROPOSAL.md`](docs/SHADOW-GUI-PROPOSAL.md). The page file
`addon/shadow_page.conf` is **generated** by `scripts/gen_shadow_page.py`
(edit the script, rerun it) — don't hand-edit it. It needs a `force-shadow`
build with the dot-matrix top bar, plain frames, and draggable envelope
support. Not on the touchscreen page (web panel only): the mod/aftertouch/
expression matrices, filter cutoff/resonance, tone level/pan, key-follow and
velocity curves, Patch/Perf mode.

### Q-Link

`addon/Force JV880 Control.xtk` is a 14-knob Q-Link template, generated by
`scripts/build_xtk.py`.

## Why JV-880 and not Osirus (Virus)

This project first attempted porting `schwung-virus`'s **Osirus** module
(Gearmulator's DSP56300 JIT emulator running real Virus firmware). That
port is **not viable on the Force**: Gearmulator's JIT compiler only has
native codegen backends for x64 and aarch64, the Force is 32-bit ARMv7, and
the `Jit` class is an unconditional member of `DSP` — even code paths that
would never execute on an unsupported architecture still have to link, which
they don't (confirmed via a real, reproduced link failure). Fixing that
would mean patching the vendored Gearmulator library's own class structure,
not just writing a host shim, and even then real-time performance on the
Force's weaker Cortex-A17 was an open, likely-unfavourable question
(Gearmulator's own docs say even *JIT-compiled* execution on the Move's
faster Cortex-A72 barely holds real-time for the lightest model).

Mini-JV has no such problem: it's a plain, portable C++ interpreter (an
H8/300 MCU emulator plus PCM rendering), no JIT anywhere, and the upstream
README already reports ~38% CPU on Move's own CM4 — real headroom rather
than a JIT-dependent margin. Measured directly on this Force
(`tools/render_test`, cross-compiled for ARMv7, run on-device against real
ROMs): **2.81x real-time**.

## Requirements

- A Force running [MockbaMod](https://github.com/MockbaTheBorg/MockbaMod).
- The separate [`force-audio-jack`](https://github.com/sd88me/force-audio-jack)
  addon, enabled once — it owns the shared audio-injection tap this module
  depends on rather than bundling its own.
- Your own JV-880 ROM dump (see below — not included).
- [`force-shadow`](https://github.com/sd88me/force-shadow), only if you want
  the touchscreen editor page.

## ROMs and expansion cards

Not included — copyrighted Roland firmware. You need your own JV-880
**v1.0.0** ROM dump (v1.0.1 does not work):

- `jv880_rom1.bin` (32KB)
- `jv880_rom2.bin` (256KB)
- `jv880_waverom1.bin` (2MB)
- `jv880_waverom2.bin` (2MB)
- `jv880_nvram.bin` (32KB) — **optional**: the engine falls back to a
  zeroed NVRAM buffer if it's absent, and writes/persists this file itself
  once you save a patch or performance

Place these files in `addon/roms/` before building/deploying.

**SR-JV80 expansion cards** are also supported — the same scanning/
unscrambling logic as upstream `schwung-jv880` is linked in verbatim. Several
cards can be used at once:

- Place expansion ROM files in `addon/roms/expansions/`
- Filenames must contain `SR-JV80` (e.g. `SR-JV80-01_Pop.bin`,
  `SR-JV80-04_Vintage_Synth.bin`)
- Files are automatically unscrambled on first load, with a patch cache
  speeding up subsequent loads
- 8MB cards: SR-JV80-01 through SR-JV80-19 (Pop, Orchestral, Piano, Vintage
  Synth, World, Dance, etc.)
- 2MB cards: SR-JV80-97, 98, 99 (Experience series)

## Installation

**From a release (no build needed):** download `ForceJV880-<version>.zip`
from the Releases page (under *Assets*, not the "Source code" archives) and
unzip it onto the SD card root, overwriting the old files in
`AddOns/ForceJV880` (your ROMs stay put). On a first install, copy your ROM files
into `AddOns/ForceJV880/roms/`. Then run the `manage.sh ENABLE` steps (2 and 3)
below on the device.

**From a checkout:**

```
scripts/deploy.sh user@force-ip
```

This is equivalent to, and replaces, these manual steps:

1. Assemble the folder with `scripts/package.sh --stage <dir>` (`addon/` +
   `build/jv_host` + `web/`) and copy `<dir>/AddOns/ForceJV880/` to the Force.
2. Run `AddOns/ForceJV880/manage.sh ENABLE`.
3. Run `AddOns/ForceJV880/web/manage.sh ENABLE`.

Your ROM files must already be in `addon/roms/` (and expansion files in
`addon/roms/expansions/`) before running `deploy.sh` — it copies them over
with the rest of the folder. (Release zips never include ROMs.)

You'll also need to enable the separate `force-audio-jack` addon once (its
own `manage.sh ENABLE`) — this module's own `manage.sh ENABLE` does **not**
touch `LD_PRELOAD` or restart `acvs` itself; `force-audio-jack` owns arming
the shared tap exclusively.

**jv_host is never auto-launched at boot.** Start and stop it manually from
the nodeServer Modules page (`/moduler`) after every boot/`acvs` restart —
`AUTOLAUNCHABLE` is deliberately `false` in `NSMODULE.json`. A voice must
never be attached before an `acvs` restart, so always start it *after* boot,
from that page, and stop it there before restarting `acvs` or rebooting.

## Building

```
./scripts/build.sh
```

Requires Docker (builds an armhf/QEMU image automatically). Output:
`dist/ForceJV880/`, a ready-to-copy addon folder (minus your ROM files).

## Layout

```
src/
  mcu.cpp/.h, mcu_opcodes.cpp/.h, pcm.cpp/.h, lcd.h   verbatim DSP core
  resampler_fixed.h    verbatim except one NEON portability fix (see DESIGN.md)
  jv880_plugin.cpp     Schwung's v2 plugin wrapper, verbatim except two
                       SCHED_FIFO removals (see DESIGN.md)
  jv_host.cpp          this port's own host shim (new code)
  plugin_api_v1.h      Schwung's plugin ABI (MIT-licensed for external use)
  rtmidi/              vendored RtMidi (same copy force-maze/force-acid use)
  forceAudioInject.h   shared-memory ring layout, vendored from force-audio-jack
  module.json/help.json/ui.js/... other schwung-jv880 metadata, for reference
  web_ui.html          the module's own remote editor, reused verbatim (see web/)
scripts/
  Dockerfile/build.sh  native-armhf-under-QEMU build (Debian bookworm - see
                       DESIGN.md for why)
  build_xtk.py/xtk-seed.json   Q-Link .xtk template generator
addon/                the engine addon (jv_host + module.json + roms/)
web/                  the web panel addon (server.py bridge + web_ui.html +
                      remote-shim.js, served at the path web_ui.html already
                      expects for its transport - zero edits to web_ui.html)
nodeserver-integration/   home-page redirect module + ENDPOINTS.js snippet
tools/render_test/   headless render benchmark, used to measure the 2.81x
                      real-time number above (from schwung-jv880 upstream)
```
